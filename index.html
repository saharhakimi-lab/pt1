צעדים ראשונים ב-Packet Tracer

ברוכים הבאים לעולם הרשתות! בלומדה זו תלמדו איך לבנות רשת מקומית ראשונה, לחבר רכיבים, להגדיר כתובות IP ושרת DHCP, ולהבין בדיוק מה קורה ב-7 השכבות במעבר מידע.

משימה 1: היכרות עם סביבת העבודה והנחת ציוד קצה
נפתח את הסימולטור ונניח את הרכיבים הראשונים שלנו על לוח העבודה (Workspace).
  • בתחתית המסך משמאל, לחצו על קטגוריית End Devices.
  • גררו למרכז המסך שני מחשבים אישיים (PC-PT) וקראו להם PC0 ו-PC1.
משימה 2: חיבור רכיבים באמצעות סוויטש ואימות נוריות ירוקות
מחשבים אינם יכולים לדבר ישירות ללא רכיב מקשר ברשת מקומית. נוסיף מתג (Switch) ונחבר אותם.
  • נכנסים לקטגוריית Network Devices ➔ Switches וגוררים סוויטש מדגם 2960.
  • בוחרים בברק הכתום (Connections), בוחרים כבל ישר (Copper Straight-Through).
  • מחברים את פורט FastEthernet0 של מחשב PC0 לפורט FastEthernet0/1 בסוויטש.
  • מחברים באותו אופן את PC1 לפורט FastEthernet0/2.
  • חווית הצלחה: חכו כ-30 שניות עד שהנוריות הכתומות יהפכו לירוקות (Spanning Tree Protocol סוגר לולאות)!
משימה 3: הגדרת כתובות IP סטטיות ובדיקת תקשורת Ping
נלבשת את שכבה 3 (כתובות לוגיות) כדי שהמחשבים יוכלו לזהות זה את זה.
  • לחצו על PC0 ➔ עברו ל-Desktop ➔ לחצו על IP Configuration.
  • הגדירו כתובת סטטית: IPv4: 192.168.1.10 | Subnet Mask: 255.255.255.0.
  • לחצו על PC1 והגדירו: IPv4: 192.168.1.20 | Subnet Mask: 255.255.255.0.
  • פתחו את ה-Command Prompt ב-PC0 והקלידו: ping 192.168.1.20. ראיתם 4 תשובות מצליחות (Reply from...)? יש תקשורת! 🎉
משימה 4: הוספת שרת DHCP וחלוקת כתובות אוטומטית
ברשתות אמיתיות אנחנו לא מגדירים IP ידנית לכל מחשב. נביא שרת שיחלק כתובות אוטומטית!
  • גררו שרת (Server-PT) מ-End Devices וחברו אותו לסוויטש בפורט FastEthernet0/24.
  • תנו לשרת כתובת IP סטטית: 192.168.1.1 (מאסק: 255.255.255.0).
  • כנסו בשרת לבלשונית Services ➔ DHCP ➔ שנו את המצב ל-On ➔ הגדירו Start IP: 192.168.1.100 ➔ לחצו Save.
  • עברו למחשבים, שנו ב-IP Configuration מ-Static ל-DHCP וראו כיצד הם מקבלים IP אוטומטית (DHCP Request Successful)!
משימה 5: מעבר למצב Simulation ושליחת מעטפה (PDU)
נראה במו עינינו את החבילה זז ברשת בזמן אמת!
  • עברו בפינה הימנית התחתונה ממצב Realtime למצב Simulation.
  • לחצו על האייקון של המעטפה הסגורה (Add Simple PDU).
  • לחצו על PC0 כמקור, ואז על PC1 כיעד.
  • לחצו על כפתור ה-Play (או Forward) ותראו את המעטפה נעה מהמחשב לסוויטש ובחזרה!
02 — תיאוריה וחשיבה

7 השכבות (מודל OSI) ב-Packet Tracer 🌐

כאשר אתם לוחצים על מעטפה במצב Simulation ב-Packet Tracer, נפתחת חלונית המציגה את מודל השכבות. הנה מה שקורה בכל שכבה מהרגע שהפורט מחובר ועד ליישום:

שכבה 1: השכבה הפיזית (Physical Layer)
▾

מה קורה ב-Packet Tracer? חיבור הכבל (Ethernet Cable), הפורט הפיזי (FastEthernet0) והמרת המידע לאותות חשמליים/אופטיים (ביטים של 0 ו-1).

בדיקת תקינות: הנורית הירוקה בפורט מעידה על סיגנל פיזי תקין (Link Up).

שכבה 2: שכבת ערוץ הנתונים (Data Link Layer)
▾

מה קורה ב-Packet Tracer? עבודה עם כתובות פיזיות (**MAC Address**) ומסגרות (**Frames**). הסוויטש קורא בשכבה זו את כתובת ה-MAC של היעד ומעביר את הפריים לפורט הנכון בלבד.

שכבה 3: שכבת הרשת (Network Layer)
▾

מה קורה ב-Packet Tracer? עבודה עם כתובות לוגיות (**IPv4 / IPv6**) וחבילות (**Packets**). בדיקות Ping משתמשות בפרוטוקול ICMP בשכבה זו כדי לבדוק שרשת המקור והיעד יכולות לתקשר.

שכבה 4: שכבת התחבורה (Transport Layer)
▾

מה קורה ב-Packet Tracer? ניהול הקשר מקצה לקצה בעזרת פרוטוקולי **TCP** (אמין, מבוסס חיבור) או **UDP** (מהיר, ללא אישור הגעה) ופורטים של שירותים (למשל Port 80 ל-HTTP או Port 67/68 ל-DHCP).

שכבות 5-7: השיחה, המצג והאפליקציה (Session, Presentation, Application)
▾

מה קורה ב-Packet Tracer? התוכנות המופעלות בתוך המחשב/שרת: דפדפן אינטרנט (Web Browser/HTTP), שירות DHCP לקבלת כתובת, Command Prompt או שירותי DNS.
