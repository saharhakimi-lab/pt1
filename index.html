PACKET TRACER LAB 📅 תאריך עדכון:

צעדים ראשונים ב-Packet Tracer לומדה אינטראקטיבית

בניית רשת מקומית ראשונה, חיבור רכיבים, הגדרת IP ושרת DHCP, והבנת 7 השכבות במעבר מידע

האקדמיה לרשתות

משימות בנייה בסביבת הסימולטור

משימה 1: היכרות עם סביבת העבודה והנחת ציוד קצה
נפתח את הסימולטור ונניח את הרכיבים הראשונים שלנו על לוח העבודה Workspace.
  • בתחתית המסך משמאל, לחצו על קטגוריית End Devices.
  • גררו למרכז המסך שני מחשבים אישיים PC-PT וקראו להם PC0 ו-PC1.
משימה 2: חיבור רכיבים באמצעות סוויטש ואימות נוריות ירוקות
מחשבים אינם יכולים לדבר ישירות ללא רכיב מקשר ברשת מקומית. נוסיף מתג Switch ונחבר אותם.
  • נכנסים לקטגוריית Network Devices ➔ Switches וגוררים סוויטש מדגם 2960.
  • בוחרים בברק הכתום Connections, בוחרים כבל ישר Copper Straight-Through.
  • מחברים את פורט FastEthernet0 של מחשב PC0 לפורט FastEthernet0/1 בסוויטש.
  • מחברים באותו אופן את PC1 לפורט FastEthernet0/2.
  • חוויית הצלחה: חכו כ-30 שניות עד שהנוריות הכתומות יהפכו לירוקות סוגר לולאות Spanning Tree Protocol!
משימה 3: הגדרת כתובות IP סטטיות ובדיקת תקשורת Ping
נלביש את שכבה 3 כתובות לוגיות כדי שהמחשבים יוכלו לזהות זה את זה.
  • לחצו על PC0 ➔ עברו ל-Desktop ➔ לחצו על IP Configuration.
  • הגדירו כתובת סטטית: IPv4: 192.168.1.10 | Subnet Mask: 255.255.255.0.
  • לחצו על PC1 והגדירו: IPv4: 192.168.1.20 | Subnet Mask: 255.255.255.0.
  • פתחו את ה-Command Prompt ב-PC0 והקלידו: ping 192.168.1.20. ראיתם 4 תשובות מצליחות Reply from? יש תקשורת! 🎉
משימה 4: הוספת שרת DHCP וחלוקת כתובות אוטומטית
ברשתות אמיתיות אנחנו לא מגדירים IP ידנית לכל מחשב. נביא שרת שיחלק כתובות אוטומטית!
  • גררו שרת Server-PT מ-End Devices וחברו אותו לסוויטש בפורט FastEthernet0/24.
  • תנו לשרת כתובת IP סטטית: 192.168.1.1 מאסק: 255.255.255.0.
  • כנסו בשרת לבלשונית Services ➔ DHCP ➔ שנו את המצב ל-On ➔ הגדירו Start IP: 192.168.1.100 ➔ לחצו Save.
  • עברו למחשבים, שנו ב-IP Configuration מ-Static ל-DHCP וראו כיצד הם מקבלים IP אוטומטית DHCP Request Successful!
משימה 5: מעבר למצב Simulation ושליחת מעטפה PDU
נראה במו עינינו את החבילה זזה ברשת בזמן אמת!
  • עברו בפינה הימנית התחתונה ממצב Realtime למצב Simulation.
  • לחצו על האייקון של המעטפה הסגורה Add Simple PDU.
  • לחצו על PC0 כמקור, ואז על PC1 כיעד.
  • לחצו על כפתור ה-Play או Forward ותראו את המעטפה נעה מהמחשב לסוויטש ובחזרה!
משימה 6 מתקדמת: תעלומת ה-ARP בין רשתות (Cross-Subnet ARP) 🔍
במשימה זו נחקור מצב שבו מתבצע פינג בין שתי רשתות שונות דרך ראוטר, ונלמד כיצד פועל זיכרון ה-ARP המקומי בצד המקבל.
צילומי מסך מתרחיש הסימולציה (לחצו על תמונה להגדלה במסך מלא 🔍)
לחץ להגדלה
מצב 1 (לפני): פינג מ-PC0 ל-PC1 - בצד המקבל לא מופיעה מעטפת ARP (ה-Gateway כבר מוכר)
לחץ להגדלה
מצב 2 (אחרי איפוס): לאחר ניקוי טבלת ARP - המחשב המקבל יוצר בקשת ARP ל-Gateway!
  • שלב 1: בצעו Ping במצב Simulation מהמחשב השולח ברשת הראשונה 192.168.10.x למחשב המקבל ברשת השנייה 172.16.0.x.
  • שלב 2: שימו לב כי ברשת השולחת מופיעה מעטפת ARP (צבע ירוק/חיוור) לחקירת ה-Gateway, אך ברשת המקבלת מופיעה רק מעטפת ICMP (סגולה).
  • שלב 3 (איפוס הזיכרון): היכנסו ל-Command Prompt במחשב המקבל והריצו את פקודת איפוס ה-ARP: arp -d.
  • שלב 4 (ניסוי חוזר): שלחו שוב פינג במצב Simulation! כעת תראו שגם במחשב המקבל נוצרת מעטפת ARP חדשה בחיפוש אחר כתובת ה-MAC של ה-Default Gateway שלו (172.16.0.1).

❓ שאלות למחשבה ולדיון בכיתה:

שאלה 1: האם המחשב המקבל לומד את ה-Default Gateway ישירות מתוך הודעת הפינג שקיבל? ▾

תשובה: לא! המחשב המקבל אינו לומד את ה-Gateway מחבילת ה-ICMP. הודעת ה-ICMP מכילה את כתובת ה-IP של המקור בלבד. המחשב המקבל יודע שעליו לפנות ל-Gateway המקומי שלו כיוון שהוא מזהה שכתובת היעד להחזרת התשובה נמצאת ברשת מרוחקת (Subnet שונה).

שאלה 2: למה בצילום המסך הראשון לא ראינו מעטפת ARP יוצאת מהמחשב המקבל? ▾

תשובה: מפני שכתובת ה-MAC של ה-Gateway כבר הייתה שמורה בטבלת ה-ARP המקומית (ARP Cache) של המחשב המקבל (כתוצאה מתקשורת קודמת או קבלת IP מ-DHCP).

שאלה 3: מה קרה לאחר שהרצנו את הפקודה arp -d במחשב המקבל? ▾

תשובה: הפקודה מחקה את זיכרון ה-ARP. כעת, כשהמחשב המקבל נדרש להחזיר את תשובת ה-Ping ל-Gateway, לא הייתה לו את כתובת ה-MAC שלו – ולכן הוא נאלץ לייצר בקשת ARP חדשה (כפי שרואים בצילום המסך השני!).

משימה 7: חלוקת הרשת ל-VLANs וניתוב Router-on-a-Stick 🏷️
במשימה זו נלמד להפריד רשת פיזית אחת לשתי רשתות לוגיות נפרדות (VLAN 10 עבור Sales ו-VLAN 20 עבור Exec) ולחבר ביניהן באמצעות תת-ממשקים בנתב.

טבלת כתובות והגדרות מעבדת VLANs

לצפייה בטבלת ה-IP, ה-Subnet Mask, ה-VLANs והפורטים המלאים עבור כל רכיב במעבדה זו:

פירוט הכתובות והגדרות המעבדה 📊
  • שלב 1 (הקמת הטופולוגיה): הניחו שני מחשבי Sales (חברו ל-Fa0/1 ו-Fa0/2 במתג), מחשב Exec (חברו ל-Fa0/10 במתג), ונתב 2911 (חברו מפורט Gi0/0 בנתב ל-Gi0/1 במתג).
  • שלב 2 (הגדרת VLANs במתג): יצירת VLAN 10 בשם Sales ו-VLAN 20 בשם Exec, שיוך הפורטים למצב Access, והגדרת הפורט אל הנתב (Gi0/1) במצב Trunk.
  • שלב 3 (הגדרת Router-on-a-Stick): כניסה ל-CLI של הנתב, הפעלת הממשק Gi0/0 (`no shutdown`), ויצירת תת-ממשקים `Gi0/0.10` ו-`Gi0/0.20` עם Encapsulation dot1Q והגדרת ה-Gateway המתאים לכל VLAN.
  • שלב 4 (אימות תקשורת): הגדירו כתובות IP במחשבים לפי גיליון הכתובות ובצעו Ping בין מחשבים באותו VLAN, ובהמשך בין מחשבים ב-VLANs שונים דרך הנתב!
משימה 8: הקמת רשת משרדית בסיסית ללא VLANs (Single Subnet) 🌐
משימה בסיסית המיועדת לתרגול יסודות הרשת המקומית (LAN) ברמות 1–3: חיבור כבלים, הגדרת כתובות IP באותה רשת, הפעלת ממשק נתב ובדיקת תקשורת.

מבדק מסכם לרשת בסיסית (ללא VLANs)

בחן את הבנתך במושגי היסוד: כתובות IP, MAC, Subnet Mask, Default Gateway ופרוטוקולי ARP/ICMP:

  • שלב 1 (הקמת ציוד וחיווט): הניחו נתב (2911), מתג (2960) ו-2 מחשבים. חברו בכבלי נחושת ישרים (Straight-Through): PC-1 ל-Fa0/1, PC-2 ל-Fa0/2, והנתב (Gi0/0) ל-Gi0/1 במתג.
  • שלב 2 (הגדרת כתובות IP):
    • PC-1: IP: 192.168.1.10 | Mask: 255.255.255.0 | Gateway: 192.168.1.1
    • PC-2: IP: 192.168.1.20 | Mask: 255.255.255.0 | Gateway: 192.168.1.1
  • שלב 3 (הגדרת הנתב ב-CLI): היכנסו ל-CLI של Router-Main והגדירו את הממשק: 
    enable
configure terminal
interface gigabitEthernet 0/0
ip address 192.168.1.1 255.255.255.0
no shutdown
  • שלב 4 (בדיקת תקינות): לבצע Ping מ-PC-1 ל-PC-2, ובנוסף Ping מ-PC-1 ל-Default Gateway בכתובת 192.168.1.1.

7 השכבות במודל OSI ב-Packet Tracer

כאשר אתם לוחצים על מעטפה במצב Simulation ב-Packet Tracer, נפתחת חלונית המציגה את מודל השכבות. הנה מה שקורה בכל שכבה מהרגע שהפורט מחובר ועד ליישום:

שכבה 1: השכבה הפיזית Physical Layer▾

מה קורה ב-Packet Tracer? חיבור הכבל Ethernet Cable, הפורט הפיזי FastEthernet0 והמרת המידע לאותות חשמליים או אופטיים, ביטים של 0 ו-1.

בדיקת תקינות: הנורית הירוקה בפורט מעידה על סיגנל פיזי תקין Link Up.

שכבה 2: שכבת ערוץ הנתונים Data Link Layer▾

מה קורה ב-Packet Tracer? עבודה עם כתובות פיזיות MAC Address ומסגרות Frames. הסוויטש קורא בשכבה זו את כתובת ה-MAC של היעד ומעביר את הפריים לפורט הנכון בלבד.

שכבה 3: שכבת הרשת Network Layer▾

מה קורה ב-Packet Tracer? עבודה עם כתובות לוגיות IPv4 / IPv6 וחבילות Packets. בדיקות Ping משתמשות בפרוטוקול ICMP בשכבה זו כדי לבדוק שרשת המקור והיעד יכולות לתקשר.

שכבה 4: שכבת התחבורה Transport Layer▾

מה קורה ב-Packet Tracer? ניהול הקשר מקצה לקצה בעזרת פרוטוקולי TCP אמין ומבוסס חיבור, או UDP מהיר וללא אישור הגעה, ופורטים של שירותים כמו למשל Port 80 ל-HTTP או Port 67/68 ל-DHCP.

שכבות 5-7: השיחה, המצג והאפליקציה Session, Presentation, Application▾

מה קורה ב-Packet Tracer? התוכנות המופעלות בתוך המחשב או השרת: דפדפן אינטרנט Web Browser / HTTP, שירות DHCP לקבלת כתובת, Command Prompt או שירותי DNS.

תרגול פקודות בדיקת רשת בטרמינל 💻

הקלידו את הפקודה לבדיקת כתובת ה-IP בטרמינל המחשב ולאחר מכן בצעו פינג לשרת DHCP: 192.168.1.1.
